## PV.Artifact - Создание артефакта, привязанного к треку, с самодостаточностью и отчуждаемостью

> **Trigger:** Когда внутри трека нужно создать артефакт (`artifacts/YYYY-MM-DD-slug.md`) — анализ, проект, спецификацию — привязанный к треку и фиксируемый WRK.
> **Governing FPF patterns:**
>   → A.15.1 (исполнение работ — артефакт как выход)
>   → A.15.2 (план работ — привязка к PlanItem)
>   → E.24.PUB (публикация как отдельное отношение — отчуждаемость)
> **Skill dependencies:**
>   → нет

---

### PV.Artifact:1 - Problem frame

Use this pattern to create an artifact bound to a track: match it to a track's
plan item, gather context, write it self-contained and alienable, and record the
work as a WRK.

### PV.Artifact:2 - Problem

Артефакт, написанный в отрыве от трека или с внутренними ссылками на сущности
проекта, не отчуждаем: читатель не может понять его без обращения к другим
файлам. Артефакт без привязки к PlanItem не отслеживается в плане трека.

### PV.Artifact:3 - Forces

| Force | Settlement |
|---|---|
| Самодостаточность vs ссылки | Артефакт читается без обращения к другим сущностям; ссылки на внутренние коды запрещены, вместо них — краткое содержательное описание. |
| Привязка vs свободный текст | Артефакт привязан к треку и к его PlanItem («Следующие ходы»). |
| Язык | Повествование на русском; английские вкрапления — только имена собственные, названия технологий и термины без устоявшегося русского эквивалента. |

### PV.Artifact:4 - Solution

**AR.1 — привязка к треку и проверка плана.**

1. Определить, какому треку принадлежит артефакт (`SocratiCode codebase_search`
   по теме или `grep -l "<keyword>" project-vault/tracks/TRK-*.md`).
2. Проверить, есть ли работа по созданию артефакта в «Следующих ходах» трека:
   - **Есть явный пункт** → использовать как `plan_item_ref` в будущем WRK.
   - **Нет пункта, но тема совпадает** → до создания добавить пункт в «Следующие ходы», объявить в чате.
   - **Нет подходящего трека** → создать трек (Track) со `status: cue`, затем добавить пункт в «Следующие ходы».
3. Сообщить: «Артефакт [суть] относится к треку TRK-NNNN, пункт плана — [N или
   „новый пункт добавлен“]. Приступаю». Дождаться подтверждения.

**AR.2 — сбор материалов.**

1. Прочитать ProblemCard@Context трека — ядро проблемы.
2. Собрать материалы трека: ссылки на DEC, Q, RISK, CON, артефакты, WRK, дайджесты по теме.
3. При необходимости — прочитать атомарные файлы связанных сущностей.
4. Если артефакт опирается на FPF-паттерны — загрузить их из fpf-core.

**AR.3 — подготовка и написание.**

1. Создать `artifacts/YYYY-MM-DD-slug.md`.
2. Соблюдать самодостаточность и отчуждаемость: артефакт читается без обращения
   к другим сущностям проекта; ссылки на внутренние коды (DEC-NNNN, Q-NNNN,
   RISK-NNNN, CON-NNNN, INV-NN, FR-XXX-NN и т.п.) запрещены — вместо кода дать
   краткое содержательное описание.
3. Язык: русский; английские вкрапления — только имена собственные, технологии, термины без аналога.

**AR.4 — фиксация работы (WRK).**

1. Сразу после написания — создать WRK (процедура WorkRecord).
2. В `plan_item_ref` — пункт из «Следующих ходов» (из AR.1).
3. В `output_refs` — созданный артефакт.
4. Обновить «Выполненные ходы» трека; после — `python scripts/vault.py work`.
5. Если артефакт закрывает PlanItem — **удалить** пункт из «Следующих ходов»
   (выполненный пункт уже зафиксирован WRK в «Выполненных ходах»). Не
   зачёркивать `~~...~~` и не ставить `[x]`. Если частично — оставить с уточнением.

### PV.Artifact:5 - Archetypal Grounding

**Show.** Артефакты этого проекта (напр. PLAS-аудит) самодостаточны, не содержат
внутренних кодов, привязаны к треку и зафиксированы WRK.

### PV.Artifact:6 - Bias-Annotation

Соблазн — ссылаться на коды сущностей «для точности», полагая, что читатель
разберётся; это ломает отчуждаемость. Симметричный соблазн — писать артефакт
без привязки к плану трека, «просто результат». Оба — про потерю
самодостаточности и прослеживаемости.

### PV.Artifact:7 - Conformance Checklist

| ID | Requirement |
|---|---|
| CC-AR.1 | Артефакт привязан к треку и к PlanItem («Следующие ходы»). |
| CC-AR.2 | Артефакт самодостаточен; внутренних кодов сущностей в тексте нет. |
| CC-AR.3 | Повествование на русском; английское — только собственные имена/технологии/термины. |
| CC-AR.4 | Работа зафиксирована WRK с `plan_item_ref` и `output_refs`. |
| CC-AR.5 | Закрытый PlanItem удалён из «Следующих ходов» (не зачёркнут, не `[x]`). |

### PV.Artifact:8 - Common Anti-Patterns and How to Avoid Them

| Anti-pattern | Repair |
|---|---|
| Внутренние коды в артефакте | Заменить кратким содержательным описанием. |
| Артефакт без привязки к треку | Привязать к треку/PlanItem до создания. |
| PlanItem зачёркнут/отмечен `[x]` | Удалить пункт; он зафиксирован WRK. |

### PV.Artifact:9 - Consequences

Самодостаточность делает артефакт отчуждаемым (`E.24.PUB`), но запрещает
внутренние ссылки — краткое описание вместо кода. Привязка к PlanItem даёт
прослеживаемость, но требует синхронизации «Следующих ходов» при закрытии.

### PV.Artifact:10 - Rationale

`A.15.1` — артефакт как исполненный выход работы; `A.15.2` — привязка к плану;
`E.24.PUB` — публикация как отдельное отношение: артефакт должен читаться
самостоятельно, без обращения к другим сущностям проекта.
