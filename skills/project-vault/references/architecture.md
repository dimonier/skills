### 2. Key Files and Directories

| Path | Purpose |
|------|---------|
| `README.md` | Rules for vault structure and maintenance. |
| `state/` | Canonical current project state. |
| `state/constraints.md` | Regulatory and architectural constraints. |
| `sources/` | Captured originals (`captures/`) and analysis digests (`digests/`). Digest templates — `templates/digest-meeting.md` and `templates/digest-dialogue.md`. |
| `sources/captures/` | Captured originals "as-is" (transcripts, articles, pages). |
| `sources/digests/` | Short analysis digests of any sources; links to atomic files. |
| `decisions/` | Atomic decision cards (DEC-NNNN-slug.md). Discovery via `grep`/`SocratiCode` — no hand-maintained index. |
| `risks/` | Atomic risk cards (RISK-NNNN.md). Discovery via `grep`/`SocratiCode`. |
| `open-questions/` | Atomic open question cards (Q-NNNN.md). Discovery via `grep "status: open"`. |
| `contradictions/` | Atomic contradiction cards (CON-NNNN.md). Discovery via `grep`/`SocratiCode`. |
| `tracks/` | Operational tracks (`TRK-NNNN.md`). Generated summary `_index.md` via `scripts/vault.py`. |
| `work/` | Dated work records (`WRK-YYYY-MM-DD-hhmmss.md`). Generated summary `_index.md` via `scripts/vault.py`. |
| `methods/` | Reusable method descriptions (`U.MethodDescription`, A.3.2). |
| `vocabulary/` | Project glossary of terms. |
| `reports/` | Derived summaries and reports. |
| `scripts/` | Utility scripts for vault maintenance. |
| `dependencies.md` | Registry of dependencies and blockers. |
| `agenda-next.md` | Next meeting agenda. |

### 3. General `.md` File Layout

Most `.md` files consist of two parts: YAML frontmatter on top with fields like `id`, `status`, `updated`, `sources`, followed by regular Markdown per template. YAML is for machine-readable traceability; Markdown is for human-readable description.

### 4. Discovery (no hand-maintained indexes)

Entity directories (`decisions/`, `open-questions/`, `risks/`, `contradictions/`, `methods/`) have no hand-maintained `_index.md`. Discovery is via:
- **Semantic search:** `SocratiCode codebase_search` over `project-vault/`
- **Precise search:** `grep` over entity directories (e.g., `grep -l "status: open" project-vault/open-questions/`)
- **File listing:** `Get-ChildItem` / `ls` for full ID listing

Only `work/_index.md` and `tracks/_index.md` remain — auto-generated by `scripts/vault.py` after each WRK completion or track status change.
