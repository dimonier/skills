# Frameworks and Markers (Quick Reference)

Use this only as a **labeling aid**. Do not force-fit: if the text does not cleanly match, use `other` and describe the actual spine.

## Important: frameworks are hypotheses, not laws
- Treat AIDA/PAS/etc. as **labels for a structural hypothesis**, not as normative rules.
- If the text’s meaning-in-context contradicts a framework label, **drop the label**, do not force the text.

## Meaning-in-interaction reminders
- Extract meaning in a **local context** (audience/intent/role/genre/stakes) before applying labels.
- Ground key terms **from inside the text** (quotes), especially value terms (“freedom”, “truth”, “good”, “success”, etc.).
- When a sentence is prescriptive (“should/must/recommend”), label it as **normative**; when it describes reality, label it as **descriptive**.

## AIDA
- **Attention**: hook, shock, provocative question, bold claim.
- **Interest**: background, relevance, context, curiosity expansion.
- **Desire**: benefits, outcomes, social proof, transformation.
- **Action**: clear CTA, next step, ask, link, instruction.

## PAS
- **Problem**: pain framing, agitation seed, “this is broken”.
- **Agitate**: consequences, intensification, emotional amplification.
- **Solution**: mechanism, proposal, steps, product/service.

## BAB (Before–After–Bridge)
- **Before**: current state (pain/constraints).
- **After**: desired state (benefit/vision).
- **Bridge**: method, steps, proof, CTA.

## PASTOR (common marketing variant)
- **Problem**: identify the pain.
- **Amplify**: intensify pain/risks.
- **Story/Solution**: narrative and/or solution framing.
- **Transformation**: outcomes, “after”.
- **Offer**: what is proposed.
- **Response**: CTA.

## Problem–Solution (generic)
- Problem statement → constraints → solution → implementation → result.

## Narrative arc (generic)
- Setup → tension → turning point → resolution → takeaway/CTA.

## Practical markers to look for
- **Transitions**: “so”, “therefore”, “but”, “however”, “for example”, “in other words”.
- **Authority/Ethos**: credentials, named sources, references, “in CS this is called…”.
- **Logos**: cause-effect, definitions, structured lists, taxonomy, comparisons.
- **Pathos**: emotion words, urgency, stakes, fear/hope framing, validation.

## If ambiguous
When 2+ frameworks fit, list alternatives and justify with quotes. Prefer the simplest label that explains the whole spine.
