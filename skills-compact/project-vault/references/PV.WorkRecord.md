# PV.WorkRecord - Work record (WRK): atomic capture of each substantive step in a track

> **Trigger:** When a substantive step with a new result (an artifact, a decision, an analysis, a structural vault change) has been completed inside a track, and it must be recorded.

```episteme id="PV.WorkRecord" context="ProjectVault"
Grounding (FPF):
  builds_on: A.7, A.15.1, A.15.2, E.23, G.11

UseThisWhen:
  recording each completed substantive step in a track as an atomic WRK file (U.Work, A.15.1), so it is traceable via discovery tools and "Completed moves" stays current
  not for reconnaissance, small administrative actions, or obvious error fixes (typos, formatting)

Result:
  an atomic work/WRK-*.md marking the step, a "Completed moves" line, auto-regenerated indexes, and (on a substantive signal) an outbox proposal

Solution:
  W1.WhenToCreate:
    create for a substantive step with a new result (artifact via PV.Artifact, a decision, an analysis, a structural vault change) completed inside a track, traceable via grep / SocratiCode / the generated work/_index.md
    performed_under names the container: the fitting product track, or the service track for a maintenance run that fits no product track (PV.Track T.5)
    do not create for item 0 in "Next moves" (reconnaissance, freshness check), small admin actions, or fixing obvious errors
  W2.CreatingAWRK:
    determine hhmmss (the completion moment)
    create project-vault/work/WRK-YYYY-MM-DD-hhmmss.md from work/_template.md
    frontmatter: id, completed (YYYY-MM-DD hh:mm:ss), performer, performed_under; plan_item_ref (number of the completed "Next moves" item; optional for thin form); enacted_method (applied FPF pattern(s), comma-separated); input_refs (optional for thin form); output_refs; status (performed | partial | probe | rework-needed)
    body: 1–3 paragraphs about the work done, not duplicating the output artifact
    run the method-feedback pass at closure (W.4) before finalizing; on a substantive signal → emit to outbox/, otherwise leave the block empty
    add a "Completed moves" line: [[WRK-YYYY-MM-DD-hhmmss]] — FPF-pattern: the gist
    regenerate indexes after the WRK: python scripts/vault.py all (updates work/_index.md and tracks/_index.md); never edit these by hand
    if the step closes a PlanItem → remove it from "Next moves" (renumber if needed), never strike through, never [x]; partial → leave with a clarification
    new entities (DEC/TRK) → no separate index (grep/SocratiCode find them); a new track → vault.py tracks
  W3.TrackResumption:
    reading order on return: the ProblemCard@Context in the track body → "Next moves" (remaining PlanItems) → "Completed moves" (list of WRKs; open the atomic file if needed) → item 0 in "Next moves" (resumption actions, if present)
  W4.MethodFeedbackAtClosure (optional pass):
    recall "rethink events": a decision revisited ≥2 times; a skill rule that proved ambiguous; a first version corrected after checking the source (fpf-core/DPF); an owner clarification that removed an ambiguity
    emit only if ≥1 threshold holds: closes a gap in the skill or corrects a wrong rule (not a one-off fact); a clearer/more precise rule would cut decision time/error rate/reasoning length on the next pass; the same "rethink" recurred ≥2 times across cases
    do not emit situational trivia (typos, cosmetics, one-off puzzlement)
    on a substantive signal: write one message file into outbox/ (PV.Outbox) referencing the WRK id, the exact rule locus (PatternID/section), the essence, and a concrete proposed fix; never emit, on the owner's behalf, a decision that requires the owner's choice — list the options instead
    no signal → leave the block empty ("no gaps found"), an empty block is a result, not an omission

Stop:
  the step is recorded as an atomic WRK with full frontmatter, a "Completed moves" line, regenerated indexes, and a resolved (filled or explicit-empty) "Method feedback" block

Checks:
  a WRK for a substantive step with a result; not for trifles/reconnaissance
  an atomic file with full frontmatter (id, completed, performer, performed_under, enacted_method, status)
  body 1–3 paragraphs, not duplicating the output artifact; an optional "Method feedback" block may follow
  a "Completed moves" line added; indexes regenerated by vault.py all
  a closed PlanItem removed from "Next moves"
  the method-feedback pass (W.4) ran at closure; a substantive signal → outbox/, otherwise the block is explicitly empty

Antipatterns:
  a WRK for reconnaissance/a typo → do not create
  the WRK body = a copy of the artifact → 1–3 paragraphs about the work, not the content
  indexes edited by hand → only vault.py all
  a PlanItem struck through instead of removed → remove it; the WRK records it
  method feedback as a mandatory ritual recording every word → run only at closure, only when the threshold fires
  emitting a method-feedback signal on the owner's behalf → list options; do not decide for the owner

Continues:
  PV.Track (the container), PV.Outbox (method-feedback emission), PV.Artifact (the recorded output)

Reopen:
  A.15.1 / A.7 / E.23 / G.11 revision
